## Phase Goal

**As a** privacy-minded owner who already has a `trace.db` from Phase 3, **I want to** have every handoff attempt — the accepted ones, the rejected ones, and each agent leg with its own fallback trail — recorded in my own local SQLite and readable after the fact, **so that** a wrong reroute is observable later without me having to delete my existing trace or trust a claim that nothing was lost.

<objective>
Give the trace store the two tables and two event types the mesh needs, and prove them against a database that already exists. This is the half of MESH-05 that lives entirely in `paaf-trace`, and it runs in parallel with plan 04-01 because it shares no file with the `paaf-llm` package.

The load-bearing constraint is Pitfall 5: `TraceStore` applies its schema with a single `executescript(read_schema())` over `CREATE TABLE IF NOT EXISTS` statements. There is no version table, no migration runner, and no way to add a column to a table that already exists. So the design is new tables only, every column the phase will ever need declared up front, and a test that opens a pre-Phase-4 database file rather than a fresh `tmp_path` one — because the `tmp_path` fixture can never catch a missing migration.

Purpose: MESH-05 (every handoff, who was awake each turn, whether each turn was served by a fallback), OQ-5 (one row per agent leg, correlated by `turn_id`), SC#4 (per-agent fallback provenance).
Output: two new tables, two new event dataclasses, a new schema test module, and the reopen case.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| engine → trace writer | Free-text fields (`detail`, `to_agent`) carry model-influenced strings. They cross into SQL. |
| trace DB → disk | The trace is local-only; TRACE-05 forbids any egress path from it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-06 | Tampering | `HandoffEvent.as_sql` / `TurnLegEvent.as_sql` | high | mitigate | A model-authored `to_agent` or `detail` string reaching SQL. Both events use parameterized INSERTs with an explicit column list and never string interpolation; the balance test (`sql.count("?") == len(params)`) makes a hand-built query with an inlined value fail the suite. |
| T-04-07 | Repudiation | rejected handoff attempts | high | mitigate | A rejected handoff produces no `runs` row and would otherwise be invisible, so a mis-route could not be reconstructed (MESH-05 fails silently). The `handoffs` table records attempts regardless of outcome, and the round-trip test asserts the rejected shape specifically. |
| T-04-08 | Denial of Service | on-disk schema application | high | mitigate | Pitfall 5: adding a column to an existing table is a silent no-op, so the mesh would write to a column that is not there and every emit would be dropped. New tables only, and the reopen test proves it against a pre-existing file instead of a fresh `tmp_path` one. |
| T-04-09 | Information Disclosure | trace contents | low | accept | The new tables hold agent names and free-text detail from the user's own conversation. They are local-only; TRACE-05's existing no-egress control covers them unchanged and is re-run as an acceptance criterion. |
| T-04-SC | Tampering | dependency surface | low | accept | No package installed. `aiosqlite` and stdlib `sqlite3` are already pinned; RESEARCH § Package Legitimacy Audit records zero new dependencies for the phase. |
</threat_model>
