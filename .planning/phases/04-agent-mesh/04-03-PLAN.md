## Phase Goal

**As a** self-hoster whose agents can now hand off to each other, **I want to** be certain a turn always ends — with a home agent I named picking up when the mesh runs out of moves — **so that** a model that keeps bouncing the conversation around cannot burn my tokens forever, while the ordinary A→B→A hand-back I actually want still works.

<objective>
Put the wall behind the mesh and prove it is a wall. Plan 04-01 shipped a constant hop cap so nothing unbounded went out; this plan makes it the user's (`LlmConfig.hop_budget`, floor 3), makes exhaustion a *capability removal* rather than an instruction, gives the user the third mesh concept D-09 asked for (`default_agent`, the home agent), and writes the negative controls that make all of it non-vacuous: a loop is stopped, and a legitimate hand-back is not.

It also closes MESH-01's config half. The requirement is that no deterministic routing rule exists anywhere, and the mechanical guarantee of that is `extra="forbid"` — so the existing `routing_rules` negative control gets extended to the new mesh fields, and the CLI stops telling the user the peer graph is inert now that it is not.

Purpose: MESH-01 (no config-expressible routing rule), MESH-03 (hand-back without restarting; sticky awake state), D-08 (deterministic budget, tool withdrawn), D-09 (home agent), OQ-2 (exhaustion with no home agent declared).
Output: two new `LlmConfig` fields with validation, the exhaustion path, four new mesh tests, two new profile tests, and an honest `paaf profiles` / `paaf chat`.
</objective>
