## Phase Goal

**As a** user who wrote "never send private files" as a hard constraint on one of my agents, **I want to** have a small supervising model check every handoff attempt against that constraint before control actually moves — and be able to bound exactly what that supervisor is allowed to do about it — **so that** my constraint is enforced by the system rather than by hoping the routing model read it, and the supervisor itself cannot become a back door into agents I never connected.

<objective>
Build the observer. It is deliberately not a new subsystem: it is a reserved name in the profile namespace, configured exactly like any other profile, streamed through the same port and the same fallback loop, and bounded not by a mode flag but by which mesh tools it is granted. That last point is the whole design — D-04 makes its powers its tool grant, with generic-retry as the default, for the same reason D-08 withdraws the handoff tool at the hop wall: capability removal is the only mechanism that holds regardless of what a model decides.

Two verdicts exist. **Generic retry** kills the attempt and bounces it back to the calling agent, which may try again or just answer; OQ-1 rules that this reaches the caller as a *transient labelled prompt segment on that leg's message list only* — never as a widened `Role`, never in `Agent.history`, because either would re-open the dangling tool-call trap the Phase-3 message model closes by construction. **Self re-route** lets a confident observer pick a different peer, and D-06 confines that to the *calling agent's* declared peers: one graph, one guard.

The negative controls are what make this real. An observer that vetoes everything passes every positive test; an observer whose grant is decorative passes the veto test too. So the suite proves it allows a good handoff, and proves a retry-only observer cannot re-route no matter what it emits.

Purpose: MESH-06 (hard constraints enforced by the system), MESH-02 (the guard applies to the observer identically), D-03, D-04, D-05, D-06, D-12, D-13, D-14, D-15, OQ-1.
Output: `observer.py`, the observer's config surface with reserved-name validation, the veto and re-route paths, and four of the six MESH-06 rows.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
