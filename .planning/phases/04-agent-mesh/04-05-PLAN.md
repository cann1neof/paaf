## Phase Goal

**As a** user who was promised that nothing steers this assistant that I cannot read, **I want to** open the prompt inspector and see the exact explainer each agent was given, the persona I wrote for it, and every handoff tool it was offered with its description, **so that** the routing behaviour I observe has a visible cause in text I own — including for an agent that is not currently awake.

<objective>
This is Phase 4's PERS-05 enforcement point, exactly as `compose.py` was Phase 3's. Two things must become true together.

First, prompt assembly becomes per-agent (D-16 layer 3, D-17). Each profile may carry its own system prompt and persona; the explainer is generated from *its* manifest and *its* peer list and appended as its own labelled segment. `compose.py` needs no philosophical change — `compose(base_prompt, fragments)` was always a pure function taking the base as an argument — only a third ordered input and a resolution step in `Agent.system_prompt`.

Second, and this is the finding that makes the plan bigger than it looks: **a tool's name and description are prompt text that steers the model, and they are not in the system prompt.** The moment the mesh binds `transfer_to_chef` carrying chef's manifest as its description, PAAF is injecting behaviour-steering text `paaf prompt` does not show. MESH-04 says the explainer must be present verbatim in the inspector; PERS-05 says PAAF never injects instructions the user cannot see. Both are violated unless the inspector renders the bound tool surface too — so it does, under `--provenance` and `--agent`, never in the default output, whose byte-exact pipe-safe contract is untouched (OQ-3).

Purpose: MESH-04, PERS-05, D-17, D-18, D-19, OQ-3.
Output: per-agent prompts, the generated-and-overridable explainer, `paaf prompt --agent`, a visible tool surface, and the widened byte-exact invariant.
</objective>

|----------|-------------|
| YAML config → prompt | `system_prompt`, `persona`, `handoff_explainer` and `capabilities` are user-authored text that becomes model instructions. |
| generated text → model | The explainer and the tool descriptions are PAAF-generated strings that steer routing. |
| user-authored text → terminal | Manifests and overrides are rendered to a rich console. |
