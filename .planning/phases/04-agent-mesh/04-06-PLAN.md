## Phase Goal

**As a** privacy-minded owner whose conversation just bounced through three agents, **I want to** open my local trace and reconstruct exactly who was awake on each leg, every handoff that was attempted including the ones that were refused, and whether any leg was quietly served by a fallback model, **so that** a wrong reroute is a recorded fact I can find later rather than something I have to notice in the moment.

<objective>
Two things that sound separate and are one. SC#4 says "each agent applies its own fallback chain, and the trace records the full handoff chain" — and the reason they belong in one plan is that per-agent fallback provenance is exactly what the per-leg trace rows carry. `fallback_chain` is a single global field on `LlmConfig` today, so "each agent applies its own" is not implementable yet; adding `ModelProfile.fallback_chain` and turning `Agent._chain()` into `_chain(agent_name)` is required schema and engine work that CONTEXT mentions only in passing.

The trace design was settled by OQ-5: one `runs` row per agent LEG, so `served_by` and `fallback_trail` deliver per-agent provenance from columns that already exist, plus the FK-free `turn_legs` and `handoffs` tables plan 04-02 built. Correlation is by an engine-generated `uuid4` `turn_id`, never `lastrowid`, and never by a new column on `runs` — the store has no migration mechanism, so widening `runs` would be a silent no-op on every machine that has already run `paaf chat`.

The plan also closes D-11: whether an agent's pre-handoff prose is kept in the final reply becomes the user's setting, and it is honest either way because every leg's text is in the trace.

Purpose: MESH-05, SC#4, OQ-5, D-11.
Output: `ModelProfile.fallback_chain`, per-agent chains in the loop, per-leg trace drain, per-attempt handoff records, and a new force-included test module.
</objective>
