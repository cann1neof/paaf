## Phase Goal

**As a** self-hoster running a real local model through Ollama, **I want to** have my awake model actually receive the handoff tools and have its choice understood, **so that** the mesh I can see working against the fake also works against the model I actually run — with the framework's tool vocabulary still confined to the one file that is allowed to know about it.

<objective>
Give the real adapter the other half of the tool-calling port. Plan 04-01 declared `ToolCallingChatAdapter` and taught `FakeAdapter` to satisfy it; this plan teaches `LangChainAdapter` to satisfy it too, which is the moment the mesh stops being a test fixture.

The whole change is small by design and that is the point: `stream_with_tools` is the existing `stream` plus a `bind_tools` call plus one post-drain assignment, and `_tool_calls_of` is the twin of the already-proven `_usage_of`. The framework does the partial-JSON reassembly; PAAF adds the aggregation-then-read discipline it already uses for token counts.

This plan also closes Assumption A1. RESEARCH found the ChatOllama tools-kill-streaming issue closed upstream well before the pinned `langchain-ollama==1.1.0`, but inferred it from an issue closure rather than an executed check. The check is cheap, the machine already has both gate models, and a negative result changes the adapter's design rather than a constant — so it runs early. It runs as a scratch script, not a test, because the suite is `--disable-socket`, and it blocks nothing, because the mesh suite runs on the fake.

Purpose: MESH-01 against a real provider; MODEL-08 (no framework type crosses the port); Assumption A1 disposition.
Output: three adapter additions, offline tests for them, and a recorded A1 result.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| adapter → provider | Tool names and descriptions leave the box in every request to a cloud profile. |
| provider → adapter | Streamed chunks and aggregated tool-call JSON are untrusted provider output. |
| adapter → engine | Only PAAF types may cross back (MODEL-08). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-15 | Information Disclosure | `_translate` / `_scrub` on the `bind_tools` path | high | mitigate | A resolved API key appearing in a tool-binding error message. The new failure path goes through the existing `_translate` + `_scrub` boundary rather than raising raw — the same control T-03-04 established, extended to a new raise site. |
| T-04-16 | Tampering | `_tool_calls_of` | high | mitigate | Reading `tool_call_chunks` mid-stream yields partial JSON, which would produce a `ToolCall` with a truncated target name that the peer guard would then reject for the wrong reason. The read is off the summed aggregate only, mirroring `_usage_of`, and is asserted against stub aggregates offline. |
| T-04-17 | Spoofing | provider-returned tool call | high | mitigate | A provider (or an injected conversation) returning a tool name that was never bound. The adapter does not resolve names at all — it hands the raw `ToolCall` to `mesh.resolve_handoff`, which validates against `awake.peers` (Pitfall 4). The adapter deliberately has no authority here. |
| T-04-18 | Tampering | port leakage | medium | mitigate | The framework's `TextAccessor` (a `str` subclass) crossing the port through the new streaming method. The `str(...)` guard is copied verbatim from `stream` and asserted by an offline test that every yielded value is exactly `str`. |
| T-04-19 | Information Disclosure | live A1 check | low | accept | The script talks to localhost Ollama only, with no key and no cloud profile. It is not in CI and reads no secret. |
| T-04-SC | Tampering | dependency surface | low | accept | No package installed; the `[engine]` extra's exact pins are unchanged. RESEARCH § Package Legitimacy Audit records zero new dependencies for the phase. |
