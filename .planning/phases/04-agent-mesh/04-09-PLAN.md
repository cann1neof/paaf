## Phase Goal

**As a** self-hoster deciding whether to trust this assistant with my conversation, **I want to** read an accurate description of what the mesh guarantees, what it merely supervises, and what leaves my machine when I point the supervisor at a cloud model, **so that** I can verify the offline and no-hidden-instructions promises rather than take them on faith — which is the whole reason I chose software I can run myself.

<objective>
Close the phase by writing down what is true. Three things in this phase are easy to overclaim and the project's own commitments forbid overclaiming them.

**The constraint-enforcement caveat.** D-13 ruled that the observer counts as "the system" for MESH-06, and that ruling is coherent only because the observer is on by default. The honest version — which the docs must carry — is that free-text constraints are enforced by a supervising model, that the mesh announces itself when it is running unobserved or when the supervisor is unreachable, and that the one thing deterministic in every configuration is the peer-graph guard. RESEARCH's Security Domain names the failure directly: free-text constraints interpreted inconsistently give false assurance, and the mitigation is honest documentation.

**The observer egress path.** CONTEXT asks for this line by name. A user who points the reserved observer at a cloud endpoint and widens its window ships a slice of conversation off-box on every handoff attempt, including rejected ones — a frequency profile quite unlike a normal reply. The schema makes it declarable; the docs have to make it visible.

**The deliberate boundaries.** Four things this phase did not build were decisions, not omissions, and one of them the founder flagged as really important for v2. Writing them down is what keeps a later reader (or a later planner) from either re-litigating them or shipping them by accident.

Then the phase gates run together, at one commit, and a human reads the honesty wording before it ships.

Purpose: MESH-06's honest disclosure, PERS-05's public statement, MESH-01/04/05's user-facing description, and the SC#5 gate.
Output: an agent-mesh section in ARCHITECTURE.md, the durable record in DECISIONS.md, and three green gates.
</objective>
