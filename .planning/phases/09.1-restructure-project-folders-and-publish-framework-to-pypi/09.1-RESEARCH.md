# Phase 09.1 Research: Restructure project folders and publish framework to PyPI

## Phase Context & Goals
The goal of this phase is to dismantle the current monorepo workspace (`packages/*`) and separate the project into three isolated domains, all located under the `~/Documents/repos/paaf/` wrapper directory. Shared git history is explicitly sacrificed in favor of clean repository boundaries (Decision D-01). The framework components will be merged into a single Python package (`paaf`) and configured for PyPI publishing.

## Implementation Steps for Planning

1. **Repository Boundary Creation:**
   - Create the three target directories: `paaf/`, `paaf-meta/`, `paaf-packages/`.
   - Run `git init` inside each of them.
   - *CRITICAL*: Do **not** run `git add` for these subfolders from the root repo, to ensure they remain detached.

2. **Code Flattening & Refactoring (`paaf/`):**
   - **Move Code:** Map `packages/paaf-<module>/src/paaf_<module>` into `paaf/src/paaf/<module>`.
   - **Move Tests:** Map `packages/paaf-<module>/tests` into `paaf/tests/<module>` to avoid test collisions.
   - **Update Imports:** Refactor all internal cross-module imports across the codebase (e.g., replace `from paaf_core` with `from paaf.core`, `import paaf_llm` with `import paaf.llm`).
   - **Merge Dependencies:** Create a single `paaf/pyproject.toml` using `hatchling`. Read all `pyproject.toml` files in `packages/*` and merge their `dependencies` and `[project.optional-dependencies]`. Remove internal workspace dependencies (e.g., `paaf-core = { workspace = true }`).
   - **Package Setup:** Set package name to `paaf` and version to `0.1.0`.

3. **Consumer App Setup (`paaf-packages/`):**
   - Run `uv init paaf-packages` (or `uv init` inside the directory).
   - Ensure a `.git` is initialized there.

4. **Meta Repositories (`paaf-meta/`):**
   - Move `ARCHITECTURE.md`, `DECISIONS.md`, `CONTRIBUTING.md`, `README.md`, `project-docs`, `docs`, `mkdocs.yml`, and `scripts` into `paaf-meta/`.

5. **PyPI Workflow:**
   - Create `.github/workflows/publish.yml` in `paaf/`.
   - Trigger on `push` with `tags: ['v*']`.
   - Use standard `pypa/gh-action-pypi-publish` with `uv build` or `hatch build`.

> [!WARNING]
> **CRITICAL GSD WORKFLOW PITFALL**
> GSD's automated workflow (execution, state tracking, and atomic commits) depends on the `.planning/` directory and the root `.git` repository at `~/Documents/repos/paaf/`.
> - **DO NOT** delete the root `.git` directory during this phase.
> - **DO NOT** move `.planning/`, `.agents/`, or `.claude/` into `paaf-meta/` as part of the automated plan execution.
> - Moving or deleting these mid-phase will cause GSD to crash when it attempts its post-plan commit.
> - **Mitigation:** The plan should construct the 3 subfolders, run `git init` inside them (nested git repos), and move the source code. Leave `.planning/`, `.agents/`, and the root `.git` untouched. At the very end of the phase, instruct the user to manually relocate them and delete the root `.git` after GSD completes the phase.

## Validation Architecture

The workflow relies on this section to build the verification strategy.

- **V-01: Git Independence**
  - Verify `.git` exists independently in `paaf/`, `paaf-meta/`, and `paaf-packages/`.
- **V-02: Framework Code Structure**
  - Assert that the `packages/` directory is completely empty or deleted.
  - Assert `paaf/src/paaf/core`, `paaf/src/paaf/llm`, etc., exist.
  - Assert `paaf/tests/` exists and contains subdirectories for all modules.
- **V-03: Import and Lint Sanity**
  - Run `cd paaf && ruff check .` and `mypy src/paaf/` to prove that renaming `paaf_core` to `paaf.core` did not break internal symbol resolution.
- **V-04: Test Suite Execution**
  - Run `cd paaf && pytest tests/` with the no-network arguments (`--disable-socket --allow-unix-socket`). Ensure all tests pass with the new unified import paths.
- **V-05: Build & Packaging Verification**
  - Run `cd paaf && uv build` (or `hatch build`).
  - Extract the resulting `.whl` in `paaf/dist/` and list its contents to guarantee that ONLY `paaf/*` module code is shipped and that `tests/` are explicitly EXCLUDED.
- **V-06: Consumer Scaffold**
  - Assert `paaf-packages/pyproject.toml` exists.
  - From `paaf-packages/`, run `uv add ../paaf` to prove the combined package is structurally sound, installable, and exposes the expected submodules.
- **V-07: CI/CD Presence**
  - Assert `paaf/.github/workflows/publish.yml` is present, triggers on `v*` tags, and uses standard PyPA release actions.
