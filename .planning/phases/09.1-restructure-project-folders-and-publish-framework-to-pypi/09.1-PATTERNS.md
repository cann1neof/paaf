# Phase 09.1 Patterns: Restructure project folders and publish framework to PyPI

## 1. Unified Framework Configuration
**File:** `paaf/pyproject.toml` (Created)
- **Role:** Main package configuration for the consolidated `paaf` framework, replacing the workspace setup and individual `packages/*/pyproject.toml` files.
- **Data flow:** Merges metadata, base dependencies, and optional dependencies (e.g., `[engine]` for `paaf-llm`) from the previous module-specific `pyproject.toml` files into a single `hatchling`-based configuration. Drops the internal workspace `{ workspace = true }` declarations. Sets version to `0.1.0`.
- **Closest Analog:** `packages/paaf-llm/pyproject.toml` and root `pyproject.toml`.
- **Code Excerpt:**
  ```toml
  [project]
  name = "paaf"
  version = "0.1.0"
  description = "PAAF framework"
  requires-python = ">=3.12"
  dependencies = [
      "pydantic>=2.13",
      "ruamel.yaml",
      "cryptography",
      "filelock",
      "pyyaml>=6.0.3",
      "click>=8.4",
      "rich>=15",
      "aiosqlite"
  ]
  
  [project.optional-dependencies]
  engine = [
      "langchain==1.3.14",
      "langgraph==1.2.10",
      "langchain-ollama==1.1.0",
      "langchain-anthropic==1.4.8",
      "langchain-openai==1.4.1",
  ]
  
  [build-system]
  requires = ["hatchling"]
  build-backend = "hatchling.build"
  ```

## 2. GitHub Actions PyPI Publisher
**File:** `paaf/.github/workflows/publish.yml` (Created)
- **Role:** Automates the publishing of the `paaf` framework wheel and sdist to PyPI.
- **Data flow:** Triggered by git pushes with tags matching `v*`. Builds the distribution using `uv build` or `hatch build` and uploads via the standard PyPA GitHub Action.
- **Closest Analog:** Standard CI setups in `.github/workflows/ci.yml` but using `pypa/gh-action-pypi-publish`.
- **Code Excerpt:**
  ```yaml
  name: Publish to PyPI
  
  on:
    push:
      tags:
        - 'v*'
  
  jobs:
    publish:
      runs-on: ubuntu-latest
      environment: pypi
      permissions:
        id-token: write  # required for trusted publishing
      steps:
        - uses: actions/checkout@v4
        - name: Install uv
          uses: astral-sh/setup-uv@v6
        - name: Build
          run: uv build
        - name: Publish package
          uses: pypa/gh-action-pypi-publish@release/v1
  ```

## 3. Framework Source Code Refactoring
**Files:** `paaf/src/paaf/*` and `paaf/tests/*` (Modified/Moved)
- **Role:** Consolidates all modules (`paaf_core`, `paaf_llm`, `paaf_session`, `paaf_trace`, `paaf_voice`) into subpackages of a single namespace `paaf` (`paaf.core`, `paaf.llm`, etc.).
- **Data flow:** Source and test files are physically moved into the new `paaf/src/paaf/` and `paaf/tests/` layout. Internal cross-imports are updated from top-level packages to dot-separated subpackages.
- **Closest Analog:** Existing `packages/paaf-*/src/paaf_*` module structures.
- **Code Excerpt (Import Updates):**
  ```python
  # Old Import (e.g. from packages/paaf-llm/src/paaf_llm/profile.py)
  from paaf_core import ReloadTier, Endpoint
  from paaf_trace import TraceStore
  
  # New Import (in paaf/src/paaf/llm/profile.py)
  from paaf.core import ReloadTier, Endpoint
  from paaf.trace import TraceStore
  ```

## 4. Consumer App Scaffold
**File:** `paaf-packages/pyproject.toml` (Created)
- **Role:** The standard entry point configuration for apps built on top of the `paaf` framework.
- **Data flow:** Scaffolds via `uv init paaf-packages`. Depends on the `paaf` framework (initially locally via `uv add ../paaf` for validation).
- **Closest Analog:** Standard `uv init` boilerplate.
- **Code Excerpt:**
  ```toml
  [project]
  name = "paaf-packages"
  version = "0.1.0"
  description = "Consumer app using PAAF"
  requires-python = ">=3.12"
  dependencies = [
      "paaf"
  ]
  ```

## 5. Test Suite Invocation Updates
**Files:** GitHub Actions CI / Local test scripts (Modified/Moved)
- **Role:** Ensure tests continue to prove zero-coupling and offline guarantees using the new unified structure.
- **Data flow:** Updates the `pytest` invocation path in CI (e.g. `uv run pytest tests/` instead of `testpaths = ["packages"]`) and ensures network isolation arguments remain (`--disable-socket --allow-unix-socket`).
- **Closest Analog:** `pyproject.toml` root configuration and `.github/workflows/ci.yml`.
- **Code Excerpt:**
  ```yaml
  # From ci.yml equivalent in paaf/
  - name: Full test suite, offline
    run: uv run pytest tests/ --disable-socket --allow-unix-socket
  ```
