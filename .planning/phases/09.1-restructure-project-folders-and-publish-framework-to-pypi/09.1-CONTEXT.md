## Phase Boundary

Splitting the current repository into three isolated domains (Framework library repo, GSD planning repo, Consumer testing repo) and publishing the framework to PyPI.

</domain>

<decisions>
## Implementation Decisions

### Git History & Repository Separation
- **D-01:** Create three detached .git repos: `paaf` (the framework), `paaf-meta` (for plannings and workflows), and `paaf-packages` (for apps built using `paaf`). All these must be inside the wrapper folder `~/Documents/repos/paaf/`. — **Reversibility:** costly — splitting across detached .git repos loses shared history and is hard to merge back.

### Framework Directory Structure
- **D-02:** Create a single top-level `tests/` directory at the root of the new `paaf/` repo, containing tests for all packages.
- **D-03:** Flatten everything into a single `src/paaf/` directory.

### Consumer Repo Setup
- **D-04:** Use `uv` to scaffold the blank slate consumer app (`paaf-packages`).

### PyPI Publishing Mechanics
- **D-05:** Start at `v0.1.0` and configure GitHub Actions to auto-publish to PyPI on tagged releases.

### the agent's Discretion
- For the consumer repo setup, the agent chose `uv` as the fastest modern standard for Python environments.

</decisions>
