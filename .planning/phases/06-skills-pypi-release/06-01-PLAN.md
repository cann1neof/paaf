<objective>
Define the core Skill manifest schema (`skill.yaml`), skill configuration store integration (`SkillConfig` in `paaf.yaml`), tool autodiscovery loader (`@tool` scanning), git clone staging in `.paaf/staging/<id>`, interactive permission review with explicit security disclosure (SKILL-05), auto-approval flags (`--yes` / `--approve-permissions`), staging rollback handling, and the `paaf skill install` / `paaf skill list` CLI interface.
</objective>

<threat_model>
- **Threat T-06-01 (Manifest Injection & Path Traversal):** Malformed or malicious skill manifests using path traversal or arbitrary string execution.
  - *Mitigation:* `SkillManifest` validates skill name using strict regex `^[a-zA-Z0-9_-]+$`, uses Pydantic `extra="forbid"`, and validates path resolution strictly within skill root.
- **Threat T-06-02 (Un-sandboxed Execution & Arbitrary Code):** Skills run in-process without sandbox isolation.
  - *Mitigation:* Display mandatory interactive security disclosure at install time stating skills run in-process with no sandbox, manifest permissions provide disclosure rather than process isolation, and MCP is recommended for untrusted code. Non-interactive sessions without `--yes` / `--approve-permissions` fail loudly.
- **Threat T-06-03 (Staging Leak & Dirty Installation):** Failed installations leave dirty files or corrupt existing skills.
  - *Mitigation:* Git clone and dependency checks occur in `.paaf/staging/<tmp_id>/`. On success, directory is atomically moved to `.paaf/skills/<skill_name>/`. On failure, installation halts and retains staging for debugging (D-08) without polluting `.paaf/skills/`.
- **Threat T-06-04 (Tool Name Collisions):** Multiple skills or built-ins offering tools with identical names.
  - *Mitigation:* Tools default to flat names, but automatically prefix with `skill_<skill_name>_<tool_name>` if a collision is detected in `ToolRegistry`.
</threat_model>

<requirements_addressed>
- SKILL-01: Skill directory & manifest structure (`skill.yaml`, tool autodiscovery)
- SKILL-02: `paaf skill install <git-url>` with git clone staging (`.paaf/staging/<id>`) and rollback
- SKILL-03: Interactive permission review & explicit security disclosure during skill install
</requirements_addressed>
