<objective>
Ship the common network-endpoint declaration interface (CORE-05) so offline enforcement is architectural rather than a scattered set of `if offline:` checks. Every network-touching component will declare its endpoints through one interface; an `Endpoint` can classify itself LAN vs non-LAN; a registry aggregates declarations. Phase 2 delivers the interface, registry, and LAN classification with a negative control (a public endpoint is correctly flagged non-LAN); Phase 9's APP-08 will iterate the registry and refuse to start on any non-LAN endpoint. This is the SC#4 endpoint half.

Phase Goal (developer-as-user story): **As a** user who will later turn on offline mode, **I want** every component to declare its network endpoints in one place, **so that** the device can refuse to start anything that would reach outside my LAN — provably, not by scattered promises.

Purpose: Making endpoint declaration a single interface now is what makes CORE-05/APP-08 enforcement possible without a later scattered-checks retrofit.
Output: `net/endpoint.py` with `Endpoint`, `NetworkComponent`, `EndpointRegistry`, and classification tests.
</objective>
