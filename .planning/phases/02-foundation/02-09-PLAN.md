<objective>
Make time-to-first-audio a number CI defends before any real audio engine exists (SC#5 CI half, TRACE-04). Using a fake TTS that emits first audio after a fixed injected delay on a controllable clock, assert BOTH (D-08): (a) accounting ACCURACY + overhead — recorded `time_to_first_audio` matches the injected delay within a tight tolerance while framework overhead stays under a small ceiling (the load-bearing half per D-09); AND (b) a fixed BUDGET ceiling on the measured value. The accuracy half proves the measurement is correct with no real engine; the budget half is a measurement/overhead-regression guardrail, EXPLICITLY NOT a shipped-latency claim (D-09). The gate runs cold, no audio hardware, no network.

Phase Goal (developer-as-user story): **As a** maintainer who cares about realtime latency, **I want** CI to catch a regression in how time-to-first-audio is measured today, using a fake TTS, **so that** when real engines arrive the metric is already trustworthy and defended — not retrofitted.

Purpose: TRACE-04 lands in Phase 2 (per roadmap) because retrofitting a latency gate is an unwinnable audit; the fake-TTS accuracy assertion is what makes the metric correct before Phase 7's real Chatterbox.
Output: A fake TTS test double, the TTFA regression test (accuracy + overhead + budget + negative control), and the `ttfa-gate` CI job.
</objective>
