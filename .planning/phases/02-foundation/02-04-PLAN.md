<objective>
Build the config subsystem in `paaf-core`: a typed Pydantic v2 schema validated on every read and write (CORE-01), atomic temp+fsync+rename persistence so a crash mid-write cannot corrupt config (CORE-02), a monotonic revision with optimistic-concurrency conflict rejection under a filelock (CORE-03), and per-field reload-tier metadata that is discoverable (CORE-06). This is the SC#3 (config half) and SC#4 (reload-tier half) slice.

Phase Goal (developer-as-user story): **As a** user editing my assistant's config from the desktop app, **I want** invalid edits rejected, crashes never to corrupt my config, and a stale concurrent edit refused instead of silently clobbering, **so that** the one YAML tree I own is always valid and never lost.

Purpose: The config tree is the durable contract every later phase reads; getting atomicity, validation, and concurrency right here prevents an unwinnable retrofit.
Output: `config/schema.py`, `config/store.py`, `config/reload_tiers.py` with paired negative-control tests.
</objective>
