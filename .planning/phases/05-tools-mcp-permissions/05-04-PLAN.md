<objective>
Build the Unified Tool Registry, Permission Engine, and Spoken Confirmation Loop across built-in, `@tool`, and MCP sources.

This plan integrates tool registration with source tagging (`builtin`, `custom`, `mcp:<server>`), collision-resilient namespacing (flat default, scoped prefix fallback D-11), permission tier assignment (`observe`, `act`, `confirm`), CLI overrides (`paaf tools permission <tool> <tier>`), and the spoken confirmation turn loop with strict clean prompt policies ("Can I use tool <name>?") and trace audit logging.
</objective>

<threat_model>
- **Threat:** Prompt injection or rogue tool call executing destructive actions without user awareness.
  - **Mitigation:** Permission Engine enforces tier lookups (`observe`, `act`, `confirm`). Any tool flagged as `confirm` triggers a hard interlock requiring explicit user confirmation before function invocation.
- **Threat:** Verbose or noisy confirmation prompts leaking complex shell payloads, file paths, or synthetic code into spoken output.
  - **Mitigation:** Clean Spoken Prompt Invariant (D-06) enforces standard, concise prompt format (`"Can I use tool <toolName>?"`), stripped of argument noise.
- **Threat:** Unresponsive user or ambiguous confirmation answer allowing unauthorized tool execution.
  - **Mitigation:** Confirmation timeouts or non-affirmative user responses are strictly treated as DENIED (D-08). The system emits a trace log, notifies the user that execution was skipped, and continues turn execution safely.
</threat_model>
