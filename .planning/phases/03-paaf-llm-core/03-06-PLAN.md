## Phase Goal

**As a** user whose local model or cloud provider can drop mid-sentence, **I want to** have the conversation move onto my next configured model — on a hard failure OR a slow/overloaded one — and keep going, **so that** losing a provider never loses the conversation, and I can see afterward exactly what happened.

<objective>
Build the pure-PAAF `Agent` engine: it composes the system prompt (via plan 03-04's composer), holds ephemeral in-memory history, runs the user-ordered fallback chain with a first-token deadline, classifies the four degraded triggers, commits to the first profile that yields a token, and drains served-by + per-fallback reasons into the trace (plan 03-02's columns). The fallback loop is hand-rolled PAAF code — the ONE thing this phase does not delegate — because LangChain's built-ins cannot express slow-first-token, cannot run framework-uninstalled (SC#1), and cannot drain per-reason traces (RESEARCH Don't-Hand-Roll). This is the "it talks" + "it survives provider loss" vertical slice, proven entirely against the fake with the framework uninstalled.

Purpose: MODEL-03 (ordered fallback surviving an unreachable provider mid-conversation), MODEL-04 (fallback also on degraded-but-reachable: timeout/5xx/429/slow-first-token), MODEL-08 (the engine is framework-free).
Output: `agent.py`, `test_fallback.py`, `test_agent_turn.py`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| adapter stream → engine | Provider failures/latency cross as PAAF exceptions/timeouts; the engine must classify, not trust |
| engine → trace store | Served-by + fallback reasons drain locally (D-06); nothing leaves the device |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-14 | Denial of Service | a degraded provider stalling the turn indefinitely | high | mitigate | The first-token deadline (`asyncio.timeout(profile.first_token_budget_s)`) bounds the wait; a stalled provider triggers SLOW_FIRST_TOKEN and the loop advances to the next profile (MODEL-04). |
| T-03-15 | Repudiation | a silent wrong-reroute | medium | mitigate | served_by + fallback_trail drain to the trace on every turn (D-06); the healthy-no-fallback negative control proves the record is non-vacuous. |
| T-03-16 | Information Disclosure | secrets leaking through trace/usage | low | accept | The engine drains the composed prompt (which by construction contains no secret — keys live in SecretStore) and token counts; no api_key value flows through turn() (key resolution is the _engine adapter, plan 03-08). |
</threat_model>
