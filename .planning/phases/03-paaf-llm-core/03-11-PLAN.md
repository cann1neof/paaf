<slice_goal>
**As a** self-hoster who put my Anthropic key in PAAF's encrypted store instead of my YAML,
**I want to** name it with `api_key_ref` and have `paaf chat` actually use it,
**so that** the credential mechanism the schema advertises is the one that works — rather than
the provider SDK's own environment variable, which is the exact thing `api_key_ref` exists to
replace.

> Slice scoped to this plan and derived from Gap 1 in `03-VERIFICATION.md`. See 03-10 for why
> no phase-level user story is stated (D-G3).
</slice_goal>

<objective>
Close **Gap 1** from `03-VERIFICATION.md` (blocks SC#2, classified 🛑 Blocker), reproduced live
twice by the verifier as
`EngineError: could not bind 'anthropic:claude-sonnet-4-5': profile declares api_key_ref
'anthropic_key' but no secret store was provided`.

Everything needed already exists and is unit-tested: `LangChainAdapter.__init__` takes a
`secret_store`, `build_engine_adapter` takes a `secret_store`, `paaf_core` ships a working
`EncryptedFileSecretStore`, and `ModelProfile.api_key_ref` exists precisely so the key value
never touches YAML (CORE-04). The single missing line is `cli._default_adapter` (`cli.py:138`),
which calls `build_engine_adapter(config)` with one argument — so `self._secret_store` is
`None` in every real invocation and ANY profile declaring `api_key_ref` dies at bind. SC#2 names
Anthropic explicitly, and Anthropic is the provider most likely to need a key.

Per the operator's decision (D-G2) this is wired, not documented away.

The design question the fix has to answer is where the store's path and passphrase come from.
Two constraints settle it. First, the store is passphrase-at-boot: only the salt is persisted,
so a passphrase must be supplied at unlock. Second, this CLI invents no filesystem conventions
— `paaf prompt` writes nothing and reads only the config the user named, and a default secrets
path guessed here would be a path Phase 9 (APP-*) later has to disagree with. So: an explicit
`--secrets` path, a passphrase from the environment or a hidden prompt, and a hard rule that
neither is touched unless a profile actually declares a reference.

Purpose: without this, the only credential path that works from `paaf chat` is the one CORE-04
was written to eliminate.

Output: `api_key_ref` works end to end from the shipped command, with the negative control that
an all-local config is never asked for a passphrase.
</objective>
