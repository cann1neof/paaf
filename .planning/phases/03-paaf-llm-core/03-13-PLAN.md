<objective>
Close the dropped wave-handoff item recorded in `03-VERIFICATION.md` and promoted to in-scope by
the operator (D-G3): **`paaf chat` never writes a trace row.**

Everything on both sides of the seam is built and verified. Plan 03-02 added `served_by` and
`fallback_trail` to the `runs` table; plan 03-06 drains them from `Agent._drain` into a
`RunEvent`; both are tested by writing through a real store and reading the real SQLite file
back. But `cli.py:284` calls `build_agent(config)` with no `trace=` sink, so `Agent._drain`
returns on its first line and nothing is ever persisted in production use. 03-07's SUMMARY
explicitly assigned this wiring to plan 03-09; 03-09's `files_modified` does not include
`cli.py`. The verifier's data-flow trace records the consequence as `✗ DISCONNECTED`.

One design decision this plan makes explicitly, because it is a decision and not an oversight:
the trace file is **named by the user**, not defaulted. `paaf prompt` writes nothing and
`paaf chat` reads only the config the user pointed at; a CLI that started creating a database at
an invented path would be writing files nobody asked for, and Phase 9 (APP-*) owns filesystem
conventions for the daemon. `--trace-db` makes the sink real and testable without PAAF choosing
a location on the user's behalf.

A structural consequence worth stating up front: `build_agent` must move inside the event loop.
The store's writer task and its bounded queue belong to the running loop, and the agent cannot
be handed a sink that has not started. That is why this plan introduces a session coroutine
rather than adding a parameter.

Purpose: SC#4's authoritative record and D-06's "each fallback trigger reason is recorded in the
trace" are currently true of the library and false of the shipped command.

Output: a working `--trace-db`, row-level assertions read back with the standard library, and
the control proving nothing is written when the flag is absent.
</objective>

5. **The store must be stopped in a `finally`.** `TraceStore.stop()` is what joins the queue and

   lose exactly the rows a failed session most needs.

   (`put_nowait`, drop-on-overflow) so disk I/O never stalls the turn. `Agent._drain` already
   calls it correctly; add no second call site.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI process → local disk | the composed prompt and turn provenance are written to a file the user named |
| turn hot path → trace queue | an emit that blocked would stall the conversation |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-41 | Information Disclosure | the `runs` table records the full composed system prompt | medium | accept | This is the phase's own D-06 / SC#4 design and `RunEvent.prompts` already carries it; the trace is local-only and the `no-network-client-in-framework` contract keeps it that way (TRACE-05 / PRIV-02). The user's exposure is bounded by the fact that the file is created ONLY when they name it with `--trace-db` — nothing is written by default. |
| T-03-42 | Tampering | trace rows lost when the command exits or the session fails | medium | mitigate | The store is stopped in a `finally`, and `stop()` joins the bounded queue so every emitted event is written and committed. `test_a_failing_session_still_flushes_its_rows` asserts a row survives a non-zero exit. |
| T-03-43 | Denial of Service | trace writes stalling the conversation | low | mitigate | `TraceStore.emit` is `put_nowait` on a bounded queue and increments a drop counter on overflow, by existing design. This plan adds no second emit call site and awaits nothing on the turn path (Constraint 6). |
| T-03-44 | Elevation of Privilege | PAAF creating a database at a path the user did not choose | medium | mitigate | No default path. `--trace-db` is required for any write, and the negative control replaces `TraceStore` with a callable that fails the test if constructed without the flag. |
| T-03-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan installs no package and edits no dependency list; `aiosqlite` already arrives through the declared `paaf-trace` dependency. The SC#1 clean-venv gate in this plan's verification would fail on an accidental dependency change. |
</threat_model>
