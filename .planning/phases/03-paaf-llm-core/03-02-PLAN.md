## Phase Goal

**As a** privacy-minded owner of the assistant, **I want to** see, after the fact, exactly which model served each turn and every fallback that happened on the way, **so that** a wrong reroute or a silently-degraded provider is observable in my own local trace, never hidden.

<objective>
Add the additive trace-schema seam the fallback engine (plan 03-06) drains into: denormalized `served_by` and `fallback_trail` columns on the `runs` table, and the matching fields + widened INSERT on `RunEvent`. This is the "nothing hidden" record for MODEL-03/04 fallbacks (D-06). Chosen shape is denormalized columns on `runs`, not a child `fallbacks` table, because the Phase-2 single-writer is fire-and-forget and never returns `lastrowid` (RESEARCH Pitfall 5) — a child table would force a writer redesign this phase does not need.

Purpose: give the fallback engine a place to record served-by + per-fallback reasons (D-06) without touching the hot-path writer contract.
Output: additive DDL, an extended `RunEvent`, and a schema test with a backward-compatibility control.

Note (schema-push gate): PAAF's only persistence is this raw-SQL SQLite trace store — there is NO Payload/Prisma/Drizzle/Supabase/TypeORM ORM in the repo. This change is plain additive DDL applied by the store's single writer via `read_schema()`; no ORM push command exists or is needed. The gate is a no-op here; the schema test is the enforcement that the columns actually land.
</objective>
