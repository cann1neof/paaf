## Phase Goal

**As a** developer who needs the agent framework to stay swappable, **I want to** have any langchain import that escapes the one designated adapter package turn CI red, **so that** the "public API never leaks framework types" guarantee (MODEL-08) is a build failure, not a good intention — including the new provider bindings this phase introduces.

<objective>
Extend the Phase-2 import-linter boundary to cover the langchain PROVIDER sub-packages the real adapter will use (`langchain_ollama`, `langchain_anthropic`, `langchain_openai`) — which are currently in NO forbidden list at all (RESEARCH Pitfall 3), so today they could be imported anywhere and leak silently. Add the single permitted edge (`paaf_llm._engine.* -> langchain*`) as an `ignore_imports` whitelist so plan 03-08's adapter is legal exactly where it should be and nowhere else. Add the paired negative control proving the extended contract bites. This lands in Wave 1 and stays green immediately because no provider import exists in real source yet — it is the guard waiting for the adapter.

Purpose: MODEL-08 (no framework-type leak) — the CI-enforced boundary half.
Output: an extended `.importlinter`, a provider-violation negcontrol fixture, and an extended boundary test.
</objective>
