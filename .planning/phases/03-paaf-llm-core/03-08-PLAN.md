## Phase Goal

**As a** self-hoster with my own Ollama boxes and cloud keys, **I want to** point named YAML profiles at real Ollama, OpenAI-compatible, and Anthropic endpoints — including two local servers as distinct profiles — and have `paaf chat` use them with no code, **so that** the proven fake-backed conversation now runs on the models I actually own.

<objective>
Swap the real LangChain/LangGraph adapter in behind the exact port the fake already proved. `LangChainAdapter` lives ONLY in `paaf_llm._engine` (the CI-whitelisted site), maps each profile to a provider string via `init_chat_model`, wires `base_url` from the profile's endpoint and `api_key` from the SecretStore by reference, and translates every framework/transport failure into the PAAF `AdapterError` subclass the engine's fallback loop already handles. It ships as the optional `[engine]` extra — never a hard dependency — so `pip install paaf-llm` (no extra) still runs the whole fake suite framework-uninstalled (SC#1/FOUND-02/MODEL-08 stay simultaneously true). Nothing about the port changes: this is the moment MODEL-08's swappability guarantee is cashed in.

Purpose: MODEL-01 (named profiles bind to real providers), MODEL-02 (Ollama / OpenAI-compatible / Anthropic), MODEL-06 (two LAN servers as distinct profiles), MODEL-08 (framework confined, optional, lazy).
Output: `_engine/__init__.py`, the `[engine]` extra in `pyproject.toml`, and a guarded `test_engine_adapter.py`.
</objective>
